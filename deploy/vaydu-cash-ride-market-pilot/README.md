# Market-scoped cash-ride pilot (develop)

**Status: prepared and tested on a disposable copy of the develop schema. Not applied anywhere.**

## What changes

Before: one global switch, `driver_cash_credit_config_v1e.ride_cash_credit`. When on, cash-ride
credit enforcement applied to **every** market. The jobs trigger reserved credit for every cash
Ride, the API rejected (CE002) every non-enrolled driver's cash ride, and every driver's status
reported `pilotEnabled=true`.

After (`supabase/migrations/20261266000000_driver_cash_credit_market_pilot.sql`):

- New `driver_cash_credit_markets_v1e(country_code, currency_code, enabled, note, updated_at)`.
- New `driver_cash_credit_market_enabled_v1e(country, currency)`. It is true only when the global
  switch is on, that market has an enabled row, and the currency matches `market_availability`.
- `driver_cash_credit_status_v1f`, `enforce_ride_cash_credit_v1e` and
  `reserve_cash_job_credit_v1e` use the market check. The bodies are the deployed bodies with only
  that line changed; this is generated by `scripts/generate-cash-credit-market-pilot.cjs` and
  guarded by `src/testing/driver-cash-credit-market-pilot.spec.ts`.
- The global switch stays the kill switch. Markets without a row keep today's non-pilot behaviour.
- Privileges mirror the global switch: only the database owner writes the table, and the check is
  executable by `service_role` only.
- **The migration enables no market.**

No API or web change is needed. The API reads `pilotEnabled` from the status RPC, so it becomes
per-market automatically. The app already shows the driver's country in the cash-ride message.

## Evidence (disposable `postgres:16`, `supabase/baseline/deployed_public_schema.sql` loaded)

- Migration applied cleanly. The rollback restored a schema byte-identical to the pre-migration
  dump (only pg_dump's random `\restrict` token differed).
- `realdb-market-pilot-test.sql`: 15/15 checks passed. All off. Global on with no market row
  stays off everywhere. GB/GBP on means GB is in the pilot and NG is not. A currency mismatch is
  ignored. The kill switch overrides everything. `reserve` stops an NG job at the market gate
  (CE001) and lets a GB job reach the existing enrolment gate (CE002). A real `UPDATE` of an NG
  cash ride is untouched, while a GB one is enforced.
- Contrast without the migration: with the global switch on, the NG driver reported
  `pilotEnabled = true`.

## Not covered by this change

Customers cannot book a cash ride yet. The booking page only creates `card`/`wallet` bookings,
nothing writes `metadata.cash_collection_mode='full_customer_charge'`, and customer cash payment is
the tenant-wide `marketplace_settings.payment_rules.cashEnabled` (off). Until a cash booking path
exists, enabling GB makes drivers see "Cash rides are enabled for you in GB" with no cash rides to
accept. **Hold step 4 until that path exists.**
