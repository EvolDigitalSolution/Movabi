# Wallet sandbox — localhost and native checkout

The original sandbox Wallet UI required the browser origin to equal the configured HTTPS callback origin. That hid the control on localhost and in Capacitor, even for the approved cohort. This change keeps eligibility, market, test-key and no-credit enforcement on the existing API; it accepts the already-allowed development origins http://localhost:3000, http://localhost:4200, http://localhost:8100 and https://localhost, plus native Capacitor clients. Other unrelated web origins remain blocked. This does not broaden backend CORS, approve another user, or accept client-provided callback URLs.

On normal hosted web, the existing same-tab checkout and return behavior stays. On localhost, an empty checkout tab is opened synchronously on the test-button click to avoid popup blocking, then navigated only after a validated provider response; the original Wallet tab stays open. If blocked, no checkout is initiated. When the customer returns focus to that tab, the existing saved attempt is checked with the authenticated API and reconciled; the checkout URL/reference alone never marks success.

On Android/iOS the existing Capacitor Browser plugin opens the hosted test checkout. When the customer closes the checkout browser with Done/back, browserFinished rechecks the saved attempt through the API. Browser failure keeps the pending attempt recoverable. This does not claim automatic native deep-link return: the existing server callback is an HTTPS web Wallet page, so the customer must close the native checkout browser to return to the app. Native app-link registration, OS behavior, real devices, and automatic universal-link routing have not been inspected or validated by this package.

Native/localhost recovery context stores only owner UUID, idempotency UUID and attempt UUID in localStorage so app/browser restart can reconcile; no access tokens or provider credentials are stored there. Existing sessionStorage context is migrated on first use. Other hosted web origins keep the prior sessionStorage behavior. Owner isolation, stale-response suppression, HTTPS provider host allowlist, confirmed test status, and spendableCredit=false remain. Source-tested origins reflect the deployed API's observed CORS; other loopback addresses/ports require separate server CORS configuration and are not represented as supported.

Executed locally: 26 pure platform/client behavioral cases, 24 existing sandbox UI cases, shell syntax, original-source guards, install/reinstall/rollback and archive integrity. Angular/Capacitor code is not exercised on a native simulator or real device here; project Vitest and mobile/admin builds run on the owner's Windows machine. There is no API/SQL change, key edit, sandbox admission change, collection/cash-pilot flag change, provider request, wallet credit, driver layout change or deployment in this package.
