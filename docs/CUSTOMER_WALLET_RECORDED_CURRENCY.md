# Customer wallet recorded-currency correction

Owner-supplied read-only development report: wallets.currency_code has a GBP default; the report contains one GBP wallet linked to a GB profile and no NGN wallet row. This does not establish the screenshot customer's individual wallet identity. Missing customer wallets were displayed as zero through AppConfig's selected/default-country currency formatter, which could fall back to GB/GBP.

This patch formats customer Home wallet badge and Wallet balance using the wallet row's own currency_code. It neither selects currency from a browser/GPS/profile preference nor converts or relabels stored balances. Valid existing GBP remains GBP regardless of an NG profile. A missing wallet is "Wallet" on the compact Home badge and "Not set up" on the Wallet screen; loading and errors are explicit, never fabricated zero. Actual zero balances retain their recorded currency (e.g. NGN 0.00). New NGN wallet provisioning is NOT implemented: it requires a separate backend change with country/tenant authority and must not be replaced by changing the global default or mutating existing wallets.

Transaction amounts use each row's explicit currency_code (or an explicit currency field); conflicting or missing currency provenance remains unavailable rather than borrowing the current wallet currency. Amounts use exact decimal strings; unsafe numeric values/invalid precision are refused instead of rounded. No FX conversion, fee recalculation, provider routing, collection or payout capability change.

WalletService's read now coalesces concurrent calls, validates owner/currency/amounts, clears stale balances on reads/failures/logout/account switches and ignores late responses by owner generation. Public wallet() consumers remain read-compatible; no known caller writes that signal. Customer history is similarly hidden for a different owner and overlapping transaction reads cannot publish over a newer read. Existing payment/top-up/settlement method bodies are byte-identical, checked by a supplemental hash; all collection remains disabled. Existing layouts are kept, with small text for setup/error states in place of an oversized fake amount.

Executed locally: 25 behavioral cases exercise production wallet read/format code with mocked external Angular/DB/HTTP dependencies; source-contract checks verify views and unchanged writer bodies. Installer installation/reinstallation/rollback and archive verification are separate checks. Full Vitest/Angular builds and signed-in acceptance are owner-run; PostgreSQL is neither required nor modified by this package.

Only three existing client files are modified (Home, Wallet page, WalletService), plus new utility/checks/spec/docs. Driver card formatting and Wallet-tab placement are not overwritten; the owner's next mobile build includes those pending driver edits. Installer verifies exact uploaded source baselines and six applied migrations, validates package bytes, backs up original files and prints guarded rollback. No git, server deployment, credentials or SQL are changed by installation.
